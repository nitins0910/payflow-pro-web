1 Page Overview & KPI Cards

The Employees page is where your entire team's payout details live — it's the source list every other page (Salary Calculation, Generate Transaction File, Beneficiary Upload File, Salary Slip) reads from. Four cards at the top give you an at-a-glance summary:

  • Total Employees — count of every record currently in your ledger.
  • Payout Bank — your company's own bank (set under Settings → Company Details). This is the bank salaries are debited from, and it's what decides which bank-specific fields this page asks for (see Section 3).
  • Disbursed This Month — total ₹ amount exported via Generate Transaction File so far this calendar month.
  • Last Export — the batch ID and date of your most recent export, so you can tell at a glance whether this month's payroll has already gone out.

2 Adding an Employee

Click + Add Employee to open the form. It's organized into three groups:

Core details (always required)

  • First / Middle / Last Name — Middle Name is optional; all three auto-uppercase as you type and can't contain spaces within a single box (use separate boxes instead).
  • Emp Code — a short numeric code unique across your whole ledger. It's padded to at least 2 digits automatically and is used to build each bank's own batch/transaction reference, so a duplicate code is rejected outright.
  • Transfer Type — Intrabank Transfer if the employee's account is with your own company bank, or Interbank Transfer otherwise. This decides which list they show up in on the Generate Transaction File page.
  • Mobile Number — a valid 10-digit Indian mobile number (must start with 6–9).
  • Email Address — used to send that employee's payslip directly from the Salary Calculation page's "Email All Payslips" button.
  • Account Number and Confirm Account Number — must match exactly (a mismatch is flagged live, before you can save). Masked by default; use the eye icon to reveal it.
  • IFSC Code and Confirm IFSC — same match-before-save rule as the account number.
⚠️ Account Number and Emp Code must both be unique
Saving an employee whose Account Number or Emp Code already exists elsewhere in your ledger is rejected with an error — this applies whether you're adding one employee manually or importing a whole CSV (Section 6).

Payroll & Compliance details (optional)

These feed the Salary Slip only — they never affect bank-file export logic, and leaving any of them blank is fine (they just show as "—" on the slip):

  • Designation and Department — free text.
  • Date of Joining — a date picker.
  • UAN (Universal Account Number) — if entered, must be exactly 12 digits.
  • PAN — if entered, must match the standard format, e.g. ABCDE1234F.

3 Bank-Specific Fields

Beyond the core details above, some bulk-beneficiary upload formats need a bit more information per employee. Which section appears is decided automatically from your company's current payout bank — switching banks later in Settings changes what this form asks for the next time you add or edit someone.

State Bank of India (SBI)

IFSC prefix: SBIN
  • No extra fields
  • Only the core details above are needed.

ICICI Bank

IFSC prefix: ICIC
  • Beneficiary Nickname
  • Up to 32 characters — used by ICICI's own "BENE Upload" format.

HDFC Bank

IFSC prefix: HDFC
  • Beneficiary Nickname
  • Beneficiary Account Type — Savings, Current, CC, or OD.
  • Beneficiary Bank Name is worked out automatically from the employee's IFSC — no field needed.

Punjab National Bank (PNB)

IFSC prefix: PUNB
  • Beneficiary Nickname
  • Address — city / branch area.
  • Max Amount / Day and Max Transactions / Day — PNB's own per-beneficiary daily fraud-safety cap, editable anytime later from PNB's Corp Admin panel.
🛡️ Missing bank fields when the file is later generated
If you skip a nickname/address/limit when adding someone, PayFlow Pro doesn't block you — a reasonable default (nickname derived from the employee's name, a generous daily cap above their last paid amount) is used automatically at the time you generate the Beneficiary Upload File. The orange ⚠ banner and row markers on this page simply flag whose record is missing these bank-specific fields, so you know who would get a default rather than your own values.

4 Search, Edit & Delete

  • Search box — filters the table live as you type, matching against employee name or account number.
  • Sortable columns — click any column header with an arrow (Name, Account Number, IFSC/Branch Code, Transfer Type, Emp Code) to sort the table by that field; click again to reverse the order.
  • Edit a row — opens the same form as Add Employee, pre-filled, so you can correct any field including bank details.
  • Delete a row — removes that employee from the ledger. This doesn't affect any file already exported in the past; those stay on the Exports page exactly as they were generated.

5 Selecting & Bulk-Deleting Rows

  1. Tick individual checkboxes, or use the header checkbox to select all visible rows.

    A bulk action bar appears showing how many rows are currently selected.

  2. Click "Delete Selected" to remove every selected employee at once.

    Useful for cleaning up a batch of test records or removing employees who've left, without deleting one by one.

  3. Click "Clear Selection" to deselect everyone without deleting anything.

6 Bulk Import & Export CSV

For onboarding a whole team at once, or backing up/editing your ledger outside the app, the Employees page supports round-tripping your data as a CSV file.

Download sample CSV

Click "Download sample CSV" to get a ready-to-fill template with the exact column headers the importer expects, plus one example row. The columns adapt automatically to your company's current payout bank — so a PNB company's sample includes the PNB-specific columns, while an SBI company's sample doesn't.

Bank-specific columnsDepends on bankSame fields as Section 3 (Beneficiary Nickname, PNB Address/Max Amount/Max Transactions, HDFC Account Type) — required only for banks that need them.

Import a CSV

  1. Click "Bulk Import CSV" and choose your file.

    Nothing is written to your ledger yet at this point — the file is only parsed and validated.

  2. Review the preview.

    Every row that parsed cleanly is shown in green as "will import"; every row that failed a check is shown in red with the exact reason (missing/invalid field, duplicate Account Number or Emp Code against your existing ledger or against another row in the same file, etc.).

  3. Confirm to import.

    Only the valid rows are added — skipped rows are never partially imported. Very large files only list the first 500 rows individually in the preview, but every row beyond that is still imported or skipped using the same rules.

Export Ledger CSV

Click "Export Ledger CSV" to download your entire current employee list in the exact same column layout the importer expects — handy as a backup, for bulk-editing in a spreadsheet, or for re-importing after changes. Like the sample CSV, the columns match your company's current payout bank.

7 Beneficiary Upload File (Free)

Before an employee can actually receive a payroll transfer through your bank's bulk upload, most banks first require them to be registered as a Beneficiary / 3rd Party Payee on your bank's own net-banking or CMS portal. Click "📄 Beneficiary Upload File" on this page to generate that registration file straight from your saved employee list — built entirely client-side, so it never touches your wallet or credits.

This is a separate, one-time-per-employee step from the paid payroll export on the Generate Transaction File page. For the full walkthrough — including exactly what each bank's file looks like and where to upload it — see the How to Generate Bank Payment Files guide, Section 2.

8 Frequently Asked Questions

Why can't I save an employee with an account number I already used?

Account Number (and Emp Code) must be unique across your whole ledger — this is enforced whether you add one employee manually or import a CSV, so the same person can never accidentally end up in your payroll twice.

I switched my company's payout bank — do I need to re-enter all my employees?

No. Existing employee records stay exactly as they are. The form (and CSV columns) will simply start asking for that new bank's specific fields going forward — the orange ⚠ banner on this page will flag anyone missing them if you want to fill those in.

What happens to an employee's data if I delete them?

They're removed from the ledger and won't appear in future Salary Calculation, Generate Transaction File, or Beneficiary Upload File runs. Any file already exported in the past is untouched — the Exports page keeps a snapshot of every past batch exactly as it was generated.

Does deleting or bulk-importing employees cost credits?

No — adding, editing, deleting, searching, and both CSV import and export are completely free. Credits are only ever consumed when you click "Export File" on the Generate Transaction File page.

My CSV import skipped some rows — how do I fix them?

The preview modal shows the exact reason for every skipped row (missing field, wrong format, duplicate Account Number/Emp Code, etc.). Fix those rows in your spreadsheet and re-upload — rows that already imported successfully won't be duplicated as long as their Account Number and Emp Code stay unique.
